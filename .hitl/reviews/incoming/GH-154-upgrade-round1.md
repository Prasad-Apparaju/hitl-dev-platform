### Decide

**1. A stray `tsconfig.json` at the plugin root will ship with the release.** `hitl-claude-plugin/tsconfig.json` (untracked, 3 lines: `{ "extends": "./.claude-plugin/types/tsconfig.json" }`) was written at the same second as `.claude-plugin/types/` (Oct 6 09:00:25), the type scaffold Claude Code's plugin tooling drops; the scaffold ignores itself (`.claude-plugin/types/.gitignore` is `*`) but the root file does not. `scripts/build.sh` does not create or remove it, and `scripts/release.sh:105` runs `git -C "$PLUGIN_DIR" add -A`, so the 2.18.0 build commit would carry a tsconfig that points at an ignored directory. Add `tsconfig.json` to the plugin `.gitignore` beside `evals/results/`, or delete it before running release.sh.

**2. No Upgrading sentence for a 2.17.0 repo, which sees a new untracked file on every prompt.** CHANGELOG.md `## [2.18.0]` has `### Added` only. The hook wrappers in an already-onboarded repo call the plugin's scripts, which from 2.18.0 write `.hitl/breadcrumb.txt` on every prompt and every status-line refresh whether or not `breadcrumb` is set (check 4). Until the ignore line lands, `git status --short` shows `?? .hitl/breadcrumb.txt` (proven in a repo with `.hitl/current-change.yaml` committed), and `git add -A` or `git add .hitl` would commit it. The changelog says "ignored by git; onboarding and `/hitl:dev-update` add the ignore line", which is true, but a 2.17.0 user reads nothing that tells them to act. One sentence: after upgrading, run `/hitl:dev-update` once (Step 4.9 adds the line), or append `.hitl/breadcrumb.txt` to `.gitignore` yourself.

### Minor

**3. Two #151 claims in the changelog are broader than the package.** (a) "Issue numbers and version lessons are gone from skill bodies": the built skills still carry 28 `#NNN` references, including in the three named skills, for example `skills/dev-start-change/SKILL.md:239` ("plugin issue #26"), `:253` ("See issue #14."), `:260` ("(#111)"), `skills/dev-start-brownfield/SKILL.md:174` ("(#10)"), `:192` ("issue #47"), `skills/dev-update/SKILL.md:136` ("plugin issue #29"), `:235` ("(#82)"). The wiring test allows this: `ci/wiring/test_skill_guide.py:30` sets `HISTORY_CEILING = 3` per skill. (b) "Shared reference files over 100 lines open with a contents list": six shipped `shared/` files over 100 lines have no `## Contents`: command-map.md (264), getting-started.md (271), usage-guide.md (372), workflow-brownfield.md (215), workflow-migration.md (252), workflow-prd.md (189). The test covers `ai/shared/*.md` in source only (`test_skill_guide.py:67`); those six are synced from docs by the build's "Syncing shared workflow docs" step. Either reword both claims to what holds ("down to at most three per skill", "the shared reference files beside the skills") or extend the sweep.

**4. Step 4.9 verifies the people/ line and not the breadcrumb line.** `skills/dev-update/SKILL.md:258-262` runs `git check-ignore -q .hitl/people/` and reports; the `.hitl/breadcrumb.txt` line appended at `:252-255` gets no check and no "✓" line. Check 2 proves the append works and is idempotent, so this is reporting only. Mirror the four-line verify for `.hitl/breadcrumb.txt`.
