### Decide

**1. The update skill syncs the two new files but never stages them.** `skills/dev-update/SKILL.md:288` (source `ai/claude/update/SKILL.md:288`): `for p in ci/first-pass ci/manifest-agentic tools/manifest-agentic ci/manifest-drift ci/adversarial ci/data-layer tools/data-layer ci/linked .github/workflows/first-pass-check.yml .github/workflows/data-layer-check.yml; do`. `ci/test-scenarios` and `.github/workflows/test-scenarios-check.yml` are missing, so the commit at line 307 ("chore(hitl): sync CI validators") leaves both untracked on a 2.16.1 repo after `/hitl:dev-update`. The qa fences still work (they fall back to `$ROOT/shared/...`), but the CI check does not run until someone notices the untracked file. Add both paths to the loop.

**2. The Upgrading paragraph is true for the skills and not for CI.** CHANGELOG `### Upgrading`: "nothing in flight is blocked on a file that could not have existed." The sync installs `.github/workflows/test-scenarios-check.yml`, which runs `check_scenarios.py --change .hitl/current-change.yaml --stage review` on every pull request that carries a change record. For a 2.16.x change with an open PR, that job fails with FILE_MISSING (check 8) until someone runs `/hitl:qa-review-tests` or `/hitl:qa-verify-quality` once, which writes the file. Same trigger model as first-pass-check.yml, so by design, but the paragraph should say it in one sentence: run test review once on the in-flight change, or expect the new CI check to report FILE_MISSING on its PR until then.
