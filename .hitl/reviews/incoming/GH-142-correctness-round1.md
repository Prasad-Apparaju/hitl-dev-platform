## Findings

**F1 (decide): Conventions prose and the CI template disagree on what blocking mode does with a warning.** The block at ai/claude/check-conventions/SKILL.md:125-126 passes `--strict` to the validator when blocking is on; `--strict` is "exit 1 on an unwaived warning" (check_data_layer.py:741). The prose at :132 maps only "A validator exit 2 or a scorecard regression" to Violations, so a warning-only exit 1 has no stated home. ci/workflows/data-layer-check.yml:46 fails the build on any non-zero validator exit. Observed: the shipped worked example itself exits 1 under `--strict` (its q:5 warning), so a repo that copies the example and sets `blocking: true` fails CI while Conventions prose says nothing about it. Owner's call: either state that in blocking mode an unwaived warning is a violation (and say so in ai/shared/data-layer.md:48), or drop `--strict` from the validator call in Conventions and the CI template and keep it for the scorecard only.

**F2 (decide): §8.2 row 4 "an ontology entry naming a service" is not what the validator catches.** The rule (check_data_layer.py:555-582) flags a path, URL or file extension, another entity's store name, or an activity, source or file name. Ran a mutation on a scratch copy: definition "A customer purchase, served by the orders-service over gRPC" gives "data layer: 0 blocking, 1 warning", exit 0. The test plan (04-test-plan.md:159) maps row 4 to NEG-1 to NEG-5, which prove a job path and a store name, not a service. The changelog claim "names a store, job, file or endpoint" is accurate to the code; the requirement row is wider than the code. Owner's call: reword row 4 to the changelog's list, or add manifest service names to the marker set and a NEG for it.

**F3 (minor): "101 tests by mutation" is 102.** `pytest` per file: test_check_data_layer.py 61, test_scorecard.py 16, test_adapters.py 25. One-word changelog fix.

Not findings, noted for the record: the design package's "13 ADRs" live as thirteen `## ADR-n` sections in one file (02-adrs.md), not thirteen files; `scorecard.py --no-write` ignores `--report` by design ("print only"), and neither the skill nor Conventions pass the two together.
