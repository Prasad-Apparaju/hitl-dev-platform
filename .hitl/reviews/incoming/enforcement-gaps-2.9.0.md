# Enforcement gaps — checks that inspect a proxy rather than the thing

Found while fixing an unrelated settings warning on 2026-09-02, at `46271e7`. Three separate
checks, one shape: each verifies something *near* the property it is supposed to guarantee, and
passes cleanly while the property is false. Two were reproduced by accident, which is the part
worth keeping.

## G1 — the `PreToolUse` gate matches tool names, not writes

`.claude/settings.json` wires `check-hitl-context.sh` to `matcher: "Edit|Write"`. A file written
through Bash never reaches it.

Reproduced without meaning to. Under `GH-103-release-2.9.0` (`status: planning`, workflow
`release`), two new source files were created:

```
$ cat > tools/retro/records.py <<'PY' ... PY     # no gate, no prompt
$ cat > ci/retro/test_records.py <<'PY' ... PY   # no gate, no prompt
$ git status --porcelain
?? ci/retro/
?? tools/retro/
```

The gate fired only when the *next* edit to the same file used the Edit tool:

```
🔒 The design for this change is not approved yet, so code edits are on hold.
Where you are: status is 'planning'.
```

So the same bytes, to the same path, under the same unapproved change, are refused or allowed
depending on which tool spells the write. `check-hitl-context.sh` extracts `file_path` from
`tool_input`; a Bash write has no `file_path`, so widening the matcher alone does not close this —
it needs the command string parsed, or the check moved to something that sees every write.

There is a precedent for the reasoning: `init-project.sh` already declines to add MCP tools to this
matcher because the extractor cannot read their input shape (`.claude/settings.json` and
`docs/design/workflow-model/04-harness-acceptance-criteria.md` Part B §9). Bash is the same problem
with a much more common tool.

**Why it matters here:** the claim this gate makes is "code edits wait for an approved design." The
claim is currently "code edits wait for an approved design, unless written with `cat`."

## G2 — the statusLine check asserts the path, not the shape

`statusLine` must be `{ "type": "command", "command": "…" }`. A bare string is discarded by Claude
Code with no error, and the project silently falls back to whatever the user has globally.

Issue #23 item 1 hardened the `dev-update` step from "does `statusLine` exist" to "does it point at
`hooks/statusline-hitl.sh`" (CHANGELOG:586). Both a bare string and a correct object satisfy a
path assertion, so the shape bug passes the hardened check exactly as it passed the original one.

Shipped in the bare-string form from `tools/scripts/init-project.sh:278`, so every repo onboarded
by the scaffolder carried it. Also in `start-brownfield/SKILL.md:75`, `start-migration/SKILL.md:52`,
and the header comment of `hooks/statusline-hitl.sh` itself. `start-from-prd/SKILL.md:91` and
`update/SKILL.md:182` had it right, which is what makes it a drift rather than a misunderstanding.

Fixed in the source tree on 2026-09-02; **repos already onboarded still carry it**, and reach the
fix only through a `dev-update` re-sync that rewrites the key rather than finding it present.

## G3 — `derive.py verify` does not cover what `derive.py` generates

`verify` compares catalog to runtime and passes. `docs/command-map.generated.md` carries "Generated
from … **Do not edit by hand**" and is regenerated by the same tool, but nothing compares the
committed file to its own output.

```
$ python3 tools/workflow-catalog/derive.py verify      # VERIFY OK
$ python3 tools/workflow-catalog/derive.py command-map | diff - docs/command-map.generated.md
  # 30 of the 45 generated lines have no match in the 43 committed ones
```

Independently reported in `release-2.9.0.md` §6. Recorded here because it is the same shape as G1
and G2 rather than a separate incident: the check covers the derivation it was written for, and
stops one artifact short.

## The common shape

| check | what it inspects | what it misses |
|---|---|---|
| `PreToolUse` hook | the tool name | the write |
| `dev-update` statusLine | the target path | the JSON shape |
| `derive.py verify` | catalog vs runtime | catalog vs generated doc |

Each of these was hardened at least once already. None was hardened toward the property; each was
hardened toward a better proxy for it. Worth asking of the next gate: what is the smallest change
that keeps this check green and the guarantee false.
