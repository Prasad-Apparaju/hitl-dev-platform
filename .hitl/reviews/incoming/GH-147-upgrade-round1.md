## Findings

**F1 (low) — shipped-hash manifest relabels the 2.16.0 line.** `shared/ci/shipped-validators.sha256` lines 77-78 both say `# 2.16.1`, but `f21651d6…7414` is exactly what `hitl--v2.16.0:shared/ci/linked/linked.py` hashes to, and the source diff shows the line changed from `# 2.16.0` to `# 2.16.1`. The sync is unaffected (check 3 passes on the hash set), but the provenance now reads as if 2.16.0 shipped no linked.py and 2.16.1 shipped two. Restore `# 2.16.0` on line 77.

**F2 (low) — `resolve` is invoked in Step 1 prose before `$LINKED` exists.** `skills/dev-start-change/SKILL.md:47`: "An id with another repository's prefix is that repository's issue, not a change to start here: resolve it with `python3 "$LINKED" resolve <id>` and say so." The first `ROOT=`/`LINKED=` definition in that skill is at line 341; a model acting on Step 1 runs `python3 "" resolve …` in the Bash tool and gets a "can't open file" error. Every fenced call elsewhere is self-contained. Inline the one-line resolver (as line 474 does) or point at the fence.

**F3 (low) — bare-number change ids now silently stop posting from shell sites, while linked.py still accepts them.** The hook and ta-approve expression requires a non-digit before the trailing digits: `12` → empty → the hook `exit 0`s without a comment, and `GH-12-foo` → empty. In 2.16.0 `${CHANGE_ID#GH-}` turned `12` into `12`. `linked.py:101` uses `(\d+)\s*$`, which accepts `12`. The schema says `Format: GH-NNN`, so a bare id is off-schema and this is an edge; but a change file hand-edited to a bare number loses progress/approval comments after upgrade with no message. Aligning the sed to `s/.*[^0-9]\{0,1\}\([0-9][0-9]*\)$/\1/p` (or `[^0-9]*`) would match linked.py.

Scope note: "guard clean" in check 1 was read as the mangled-relative-path check plus the packaging check; the build log has no step literally named guard. The install-only SYNC_SETS entries (4 of the 30 seeded files) are not counted in migrate's "25 identical" line because present install-only files are skipped silently; that is pre-existing behaviour and not a 2.16.1 change.
