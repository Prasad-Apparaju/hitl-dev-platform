# Closing Retrospective

The last step of a change. It describes what happened, carries the unresolved work forward, and
observes how the sizing turned out — the loop that corrects the right-sizing rules over time.

**Input:** $ARGUMENTS (a change id; empty means the active change)

It collects nothing new. Everything it needs was written down before it ran.

**This step costs the person nothing.** It publishes nothing, asks nobody to approve anything, and
does not interrupt. That is what makes it honest as a floor step at every tier — including on a
tier-1 one-line fix, which must not end with a confirmation prompt.

---

## Step 1 — Find the records

```bash
CHANGE=".hitl/current-change.yaml"
[[ -f "$CHANGE" ]] || { echo "No active change. Nothing to write a retrospective about."; exit 0; }
python3 -c "import yaml;d=yaml.safe_load(open('$CHANGE'));print('change:',d.get('change_id'));print('impact:',d.get('impact_record') or '(none declared)')"
ls .hitl/reviews/*.yaml 2>/dev/null | head
```

If the change names an `impact_record` that is missing, say so plainly and carry on. The third part
will be thin, and a thin third part is honest; an invented one is not.

## Step 2 — Generate it

The document is a pure function of the records. Do not hand-write it — that is how it drifts from
what actually happened.

```bash
ROOT="${CLAUDE_PLUGIN_ROOT:-.}"
GEN="tools/retro/retro_records.py"
[[ -f "$GEN" ]] || GEN="$ROOT/shared/tools/retro/retro_records.py"
[[ -f "$GEN" ]] || { echo "retro generator not found — run /hitl:dev-update."; exit 1; }
python3 "$GEN" --change .hitl/current-change.yaml
```

It writes `.hitl/retro/<change_id>.md` and exits non-zero if the result would author a
workflow-catalog rule field (see Step 5).

## Step 3 — Read it back, and only fill real gaps

Read the generated file. The records carry the skeleton; some of them will be terse.

**You may** turn a recorded reason into a readable sentence, and name what shipped from the
requirement and the issue.

**You may not** infer a reason that was never recorded, soften one that was, or describe work no
record mentions. Where a record is silent, the retrospective is silent.

The voice is the one already defined in `ai/shared/first-pass/language.md` and linted by
`ci/first-pass/resurface.py`: describe state and movement, never who did or did not do something.

> The rollout step was left out; the change is config only.

not

> Nobody wrote a rollout plan.

The generator redacts blame vocabulary from anything it echoes. Do not reintroduce it in the
sentences you add.

## Step 4 — Show it, do not publish it

Show the person where it landed and the one line worth their attention — usually an item in *What
is still open*, or a step the rules dropped that turned out to matter.

**It stays local.** It does not go on the issue, and there is no approval prompt. Anyone who wants
it published asks for it, and that publish is an ordinary one: it carries
`Generated by Claude, approved by <name>, <date>.` and someone reads it first.

Do not ask whether to publish. Offering is a prompt, and this step does not have one.

## Step 5 — The boundary

**The retrospective records observations about the sizing rules. It never edits them.**

A mechanism that judges its own sizing decisions and then rewrites the rules it was judged by is
grading its own homework. HITL holds this line elsewhere the same way: `hitl:agentic-intake`
authors no field of the manifest the compound validators check.

This is enforced, not asserted. `retro_authors_no_catalog_field()` returns the offending keys and
the generator refuses to write when the set is non-empty; `ci/retro/test_retro_records.py` certifies
it. The guarded field set is read from the catalog itself, so a new rule field widens the ban
without anyone remembering to.

So the third part produces a note a person reads and acts on. **Changing a rule is a change**, and
goes through the normal flow like any other. If the retrospective makes a rule look wrong, open an
issue; do not edit `workflows.yaml` from here.

## Step 6 — Fold the open items forward

The unresolved items already live in the skip ledger, which resurfaces them at the next change
touching this area. Confirm the roll-up is current rather than writing a second copy:

```bash
RS="ci/first-pass/resurface.py"
[[ -f "$RS" ]] || RS="${CLAUDE_PLUGIN_ROOT:-.}/shared/ci/first-pass/resurface.py"
python3 "$RS" --change .hitl/current-change.yaml --rollup .hitl/skip-ledger.yaml --append
```

Idempotent on `(change_id, step)`. Then mark the step done and let the breadcrumb advance.

---

## Important Rules

- Collect nothing new. If it is not already written down, it does not go in.
- Never publish it, and never ask whether to publish it.
- Never edit a sizing rule from here. Observe, and open an issue.
- Silence where the records are silent. A thin retrospective is honest; an invented one is not.
